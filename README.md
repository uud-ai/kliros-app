# Клирос — богослужебный помощник

Клиросная читалка для чтецов и певчих: по выбранной дате собирает последование службы (Вечерня, Утреня, Литургия, Часы) из Октоиха, Минеи и Триоди по правилам Типикона и показывает тексты **церковнославянским языком гражданским шрифтом, с ударениями**. Работает как PWA — устанавливается на телефон или планшет и может использоваться в храме без сети.

**Демо:** <https://klirosapp.web.app>

## Возможности

- **Четыре службы суточного круга** — Вечерня, Утреня, Литургия, Часы (1-й, 3-й, 6-й, 9-й).
- **Навигация по датам** — любая дата календаря, а не только текущий день.
- **Автоматическое составление службы по уставу.** Движок сам определяет глас Октоиха по Пасхалии, знак праздника по Минее, совпадение с воскресеньем, положение в Триоди и выбирает нужные шаблоны (подробнее — в разделе «Как это устроено»).
- **Чтения Апостола и Евангелия на Литургии.** Минея указывает только номер зачала; приложение находит диапазон глав и стихов и подставляет полный текст синодального перевода.
- **Настройка под свой храм.** Можно задать тип храма (Господень / Богородичный / святого), тропарь и кондак храма — они подставляются в тропари и кондаки службы и во входные песнопения.
- **Поиск по тексту службы** с подсветкой совпадений и **закладки** по разделам (песни канона отображаются как подзакладки).
- **Удобство чтения:** светлая и тёмная темы, регулируемый размер шрифта; выбранная служба, час, тема, размер шрифта и данные храма запоминаются в браузере (`localStorage`).
- **PWA и офлайн.** Приложение устанавливается на главный экран, работает в портретной ориентации. Статика кэшируется при установке, а данные дня (`/data/**`) — по факту обращения, поэтому для работы без сети нужные даты предварительно открыть при подключении. Шрифты подгружаются с Google Fonts и тоже кэшируются.

## Состояние данных

Приложение находится в активной разработке, **корпус текстов заполнен не полностью**. Перед использованием за богослужением сверяйтесь с богослужебными книгами и указаниями настоятеля.

| Раздел данных | Что есть сейчас |
|---|---|
| `public/data/minea/` | 348 файлов `MM-DD.json` (переменные части службы святого): 12 помечены `complete`, остальные — `partial` или иные частичные статусы. Файлов нет для 18 дат, в том числе для ряда двунадесятых праздников, которые движок берёт из отдельной таблицы (`FIXED_GREAT_FEASTS`) и шаблонов |
| `public/data/templates/` | 243 шаблона: вечерня, утреня, Литургия, Часы, Октоих (по гласам и будням), Великий пост, Светлая седмица |
| `public/data/days/` | 154 готовых «рукописных» плана дней 2026 года (используются также как эталон для проверки движка) |
| `public/data/bible/`, `public/data/zachala/` | Книги Нового Завета (синодальный перевод) и таблицы зачал Апостола и Евангелия |

Триодь поддержана **частично**: реализована Пасха, новозаветные воскресенья Цветной Триоди (пока минимальной заглушкой) и воскресные службы Великого поста. Таблица Марковых глав — исключений из Типикона при совпадении неподвижных праздников с переходящими днями — пока **не заполнена**, для неё в коде оставлен только механизм.

## Быстрый старт

Требуется Node.js 22 (версия из `.idx/dev.nix`) и npm.

```bash
git clone https://github.com/uud-ai/kliros-app.git
cd kliros-app
npm install
npm run dev        # сервер разработки Vite
```

Остальные команды:

```bash
npm run build      # продакшн-сборка в dist/
npm run preview    # локальный просмотр собранной версии (в т.ч. PWA)
npm run lint       # ESLint
```

В `.npmrc` включён `legacy-peer-deps=true` — это нужно учитывать при добавлении зависимостей.

> Service worker в режиме разработки отключён (`devOptions.enabled: false`). Проверять офлайн-режим нужно на `npm run build && npm run preview`.

## Как это устроено

Вся логика устава вынесена в чистые модули без побочных эффектов, работающие одинаково в браузере и в Node — поэтому те же функции используются и в приложении, и в скриптах проверки.

| Модуль | Назначение |
|---|---|
| `src/lib/paschalion.js` | Дата православной Пасхи (алгоритм Мёуса, юлианский календарь → григорианский) и глас Октоиха на любую дату |
| `src/lib/typikon.js` | Устав соединения службы святого (Минея) и службы дня (Октоих): знаки праздника, воскресные дни, таблица неподвижных великих праздников, функция `planDayService` — план службы дня |
| `src/lib/triodion.js` | Устав Триоди (Постной и Цветной): день цикла относительно Пасхи и план службы для Пасхи и воскресных дней |
| `src/lib/readings.js` | Разбор ссылки на зачало из Минеи и вырезание текста чтения из синодального перевода |
| `src/App.jsx` | Интерфейс: выбор даты и службы, ленивая загрузка нужных JSON-файлов, поиск, закладки, настройки храма |

**Принцип данных.** `planDayService` не хранит тексты, а выдаёт декларативный план дня — какие шаблоны взять и какие переменные (Октоих, Минея, тропари) в них подставить. Тексты лежат в `public/data/` в виде JSON и подгружаются по требованию только для выбранного дня.

### Структура репозитория

```
public/data/
  minea/        # MM-DD.json — Минея, переменные части по числам
  templates/    # шаблоны служб, Октоих, Часы, Великий пост
  days/         # готовые планы дней (YYYY-MM-DD.json)
  bible/        # книги Нового Завета, синодальный перевод
  zachala/      # таблицы зачал Апостола и Евангелия
scripts/        # генерация и проверка данных
src/
  App.jsx       # интерфейс
  lib/          # движок устава
vite.config.js  # Vite + настройки PWA (манифест, кэширование)
```

## Скрипты

Запускаются из корня репозитория.

| Команда | Что делает |
|---|---|
| `npm run generate-day -- 2026-10-05` | Строит план службы дня движком и выводит в stdout |
| `npm run generate-day -- 2026-09-10:2026-12-13 --write` | То же для диапазона дат, с записью в `public/data/days/` |
| `npm run verify-typikon` | Регрессионная проверка движка устава против рукописных `days/*.json`, а также проверка, что для других лет движок не падает |
| `node scripts/verify-glas.mjs` | Сверка расчёта гласа с гласами в `days/*.json` |
| `node scripts/build-readings-data.mjs` | Разовая сборка текстов Библии и таблиц зачал из внешних источников |
| `node scripts/generate-hours-variants.mjs` | Одноразовый генератор вариантов шаблонов Часов (будни / воскресенье со святым / воскресенье с праздничным святым) |
| `node scripts/fix-liturgy-texts.mjs` | Одноразовое дополнение литургийных шаблонов неизменяемыми частями по Служебнику |

## Добавление данных

Чтобы заполнить новый день Минеи:

1. Добавьте или дополните `public/data/minea/MM-DD.json` (гражданская дата). В блоке `_meta` указываются святой, знак праздника (`rank`), источник и статус заполненности (`status`).
2. Сгенерируйте план дня: `npm run generate-day -- ГГГГ-ММ-ДД --write`.
3. Проверьте движок: `npm run verify-typikon`.

## Источники текстов и права

- **Минея и Служебник** — по сведениям в `_meta` файлов данных, тексты взяты с сайта [azbyka.ru](https://azbyka.ru) (гражданским шрифтом).
- **Библия** — синодальный перевод, [bibleonline/rst](https://github.com/bibleonline/rst) (по заявлению в скрипте сборки — общественное достояние).
- **Таблица зачал** — [paulkachur/orthodox_calendar](https://github.com/paulkachur/orthodox_calendar) (лицензия MIT).

Лицензия на код проекта пока не указана. Условия использования богослужебных текстов с azbyka.ru стоит уточнить до широкого распространения приложения.

## Технологии

React 19, Vite, [vite-plugin-pwa](https://vite-pwa-org.netlify.app/) (Workbox), ESLint. Без внешнего бэкенда: все данные — статические JSON-файлы, пользовательские настройки — в `localStorage`.

Демо развёрнуто на Firebase Hosting; конфигурация деплоя в репозиторий не включена.
